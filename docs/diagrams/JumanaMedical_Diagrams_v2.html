§2 · Request / Response Flow (14 Middleware Hops)

Every HTTP request flows through this sequence. The request logger runs on the finish hook — it captures real status code + duration AFTER the response is sent.

① helmet({ contentSecurityPolicy: false }) — X-Frame-Options, HSTS, etc.
↓
② CORS allowlist (same-origin by default; CORS_ALLOWED_ORIGINS env)
↓
③ Permissions-Policy header (geo/mic/camera/payment disabled)
↓
④ CSP middleware — 128-bit per-request nonce → req.cspNonce (Wave 22)
↓
⑤ requestLogger — JSON line per request, PHI redacted, cid stamped (Wave 24)
↓
⑥ dev-ctx (autowire _ctx) — projects x-tenant-id → req.tenantId + req.tenantScope
↓
⑦ express.json() — body parser (16 KB limit on /api/csp-report, 10 MB elsewhere)
↓
⑧ express-session — Redis (production) or MemoryStore (sandbox fallback)
↓
⑨ requireAuth → requireRole → requireTenantScope (per-route)
↓
⑩ idempotencyGuard (ONLY for money/claim routes)
↓
⑪ Route handler (47 routers, autowired)
↓
⑫ Clinical / Finance engine (pure functions, ports-injected)
↓
⑬ pg.query() — SET app.tenant_id (per-request); RLS enforces tenant scope
↓
⑭ logAudit() — hash-chained INSERT into audit_trail (Wave 21)
Failure paths: any of ⑨–⑭ throwing returns JSON error to client. The requestLogger middleware still emits a JSON log line with status=errored. CSP nonce is regenerated on each request (128-bit entropy).

§3 · Tenant Isolation Layers (Defense-in-Depth)

Three independent layers must all agree. Safety Rail #5. If any one fails, the next catches it.

LayerMechanismFailure mode caughtWave
L1 — app-layerrequireTenantScope middleware → sets req.tenantScope; every query in route handler binds tenant_id explicitlyBug in route: app-layer filter forgotten1–13
L2 — DB RLSPostgreSQL ALTER TABLE ... ENABLE ROW LEVEL SECURITY; FORCE ROW LEVEL SECURITY; + tenant_id = current_setting('app.tenant_id') policyEven a query that forgets the WHERE clause returns 0 rows for wrong tenant15–20 (100% coverage)
L3 — audit chainEvery mutating write goes through logAudit() which stamps tenant_id + hash-chains the row. Any post-hoc tampering breaks the chain.Insider with DB access tries to forge an audit row21
